Create Open Source NHI Temporal Identity Graph Research Prototype (Apache-2.0 ready)

Context / Author

Author: Shivam — CyberSecurity Professional. Use this name in the README and copyright headers.

Purpose: Build an open-source research prototype that demonstrates the temporal identity graph model for Non-Human Identities (NHIs) across cloud, IT, CI/CD, Kubernetes, and OT. The repo must be ready for public release under the Apache License 2.0.

High-level goal
Create a runnable, documented Proof-of-Concept (PoC) with:

deterministic temporal graph engine (in memory, option for Neo4j)

normalization pipeline from logs → normalized identity events

synthetic dataset generator with replayable scenarios

REST APIs for ingestion, replay, snapshot, analysis

minimal interactive frontend (React + Vite) for graph + temporal replay controls

docs, tests, license, CONTRIBUTING.md, and CI to run unit tests and example scenarios

Non-goals (do not implement)

Do not add authentication/authorization (no login).

Do not add ML or auto-remediation.

Do not build SIEM-like dashboards (keep UI focused on graph + replay + path exploration).

Do not use Next.js or server components.

Keep the prototype single-host and simple to run: docker compose up or simple uvicorn + npm run dev.

Required Tech Stack (must follow)

Backend: Python 3.10+ + FastAPI

Processing: deterministic update logic implemented in Python (clear function U(G, event) with idempotency)

Graph: in-memory property graph (networkx or custom) + optional Neo4j integration (document how to enable but default to in-memory)

Dataset & streaming: Python scripts to produce NDJSON event streams, seedable RNG for deterministic datasets

Frontend: React (Vite) — simple interactive UI (graph visualization with vis-network/d3 or cytoscape)

Persistence for demo: JSON files for snapshots (no DB by default)

Container / run: docker-compose.yml to run backend + frontend

Tests: pytest for backend logic and dataset generator

Backend: API contracts & behaviors (implement exactly)

Implement FastAPI endpoints:

POST /logs/upload

Accept NDJSON or JSON array body and source_type query param (cloud, it, ot)

For each log, parse via source-specific parser → generate zero or more normalized events (schema below) → apply U(G, event)

Return { events_generated, nodes_added, edges_added, graph_version }

POST /events/inject

Accept normalized event JSON (single) → inject into graph via U(G,event) → return updated summary

POST /events/replay

Accept path to NDJSON file or array of normalized events → replay deterministically (record graph hash at the end) → return graph hash and stats

GET /graph/snapshot?timestamp=T

Return graph projection at time T (nodes & edges active at T with metadata)

GET /analysis/reachability?source=A&target=B&k=K&timestamp=T

Return all paths ≤ K in G(T) from A to B with event evidence (list of event_ids and timestamps)

GET /analysis/blast-radius?source=A&k=K&timestamp=T

Return list of reachable nodes, path evidence, and computed risk score using default max-rule

GET /analysis/threats?timestamp=T

Return list of detected graph-pattern threats (over-delegation, orphan NHI, it→ot path) with path evidence

Normalized event schema (use Pydantic models):

{
  "event_id": "string",
  "timestamp": "ISO-8601",
  "subject": {
    "id": "string",
    "type": "HUMAN | WORKLOAD | SERVICE_ACCOUNT | PLC | HMI",
    "platform": "enterprise | aws | ci_cd | k8s | ot",
    "lifecycle_state": "ACTIVE | STALE | DECOMMISSIONED",
    "risk_score": number
  },
  "relationships": [
    {
      "label": "AUTHENTICATES_WITH | ASSUMES | ACCESSES | COMMUNICATES_WITH | CONTROLS",
      "target": {
        "id": "string",
        "type": "IDENTITY | RESOURCE"
      }
    }
  ]
}


Implement strict validation and reject malformed events with 400 and a clear error.

Core graph engine (must implement)

Implement a function U(G, event) that:

creates nodes if missing, sets first_seen when node created, updates last_seen = max(current, event.timestamp)

creates edges (source_id, target_id, label) if missing; maintain first_seen/last_seen for edges

uses idempotent operations (set unions, min/max times) so replaying same events yields identical graph

store provenance: map node/edge → list of event_ids that created/updated it

Maintain a graph_version as a hash of canonical serialization (used to assert deterministic replay)

Dataset generator (must include)

Implement CLI python -m backend.app.model.dataset_gen with flags:

--seed SEED (int, deterministic)

--days N (length of timeline)

--events PER_DAY

--scenario {baseline,cicd_compromise,cloud_ot_bridge,dormant_wakeup}

Output NDJSON normalized events (not raw logs) to examples/scenarios/*.ndjson

Include attack injections in cicd_compromise and cloud_ot_bridge that produce observable paths from human → CI/CD → cloud role → workload → OT gateway → PLC

Ensure generator produces reproducible output with given seed; include SHA256 of output file in header
